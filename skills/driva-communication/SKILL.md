# Driva Communication (exemplo público)

Redigir o comunicado interno de uma funcionalidade entregue, para que atendimento e vendas entendam o
que mudou, para quem e como usar.

## Público e tom

CS e vendas. Linguagem simples, frases curtas, sem termos de código. Foco no benefício para o cliente.

## Estrutura

Título · O que mudou · Para quem · Como usar (passos) · Limitações conhecidas · Onde tirar dúvidas.

## Imagens

Só quando o ticket ou o PR trouxer capturas; nunca gerar imagens com dados reais de clientes.

## Método

1. Ler o ticket (especificação e comentários). 2. Ler os PRs vinculados e confirmar no código o que foi
   entregue. 3. Não prometer o que não está no código. 4. Marcar dúvidas abertas.

## Iteração

Aceitar reorientação do solicitante e registrar o que mudou entre versões.

## Fora do texto

Detalhes técnicos, nomes de repositórios e dados de clientes ficam fora do comunicado.
